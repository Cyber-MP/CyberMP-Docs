| Функция | Что делает |
| --- | --- |
| `mp.spawnTask(fn)` | Запускает `fn` корутиной на следующем проходе планировщика. |
| `mp.spawnTaskImmediatly(fn)` | Запускает `fn` корутиной сразу, до первого `mp.wait`. Имя в API написано именно так. |
| `mp.setTimeout(fn, ms)` | Запускает `fn` корутиной через `ms` миллисекунд. Ничего не возвращает, отменить нельзя. |
| `mp.wait(ms)` | Приостанавливает текущую корутину на `ms` миллисекунд. `mp.wait(0)` или `mp.wait()` продолжает на следующем проходе. |
| `mp.onUpdateLoop(fn)` | Вызывает `fn` на каждом тике скриптов. Снять нельзя. Ошибка внутри `fn` теряется без сообщения. |
| `mp.getTimer()` | Счётчик миллисекунд для замера интервалов. |
| `mp.setImmediate(fn, ...)` | Только клиент. Вызывает `fn(...)` на следующем тике, до 256 вызовов за тик. |

`mp.wait` работает только внутри корутины. Задачи, таймауты, обработчики событий и команд — корутины; основное тело файла — нет. Ошибка внутри корутины печатается со стеком и останавливает только эту корутину.

```lua
mp.spawnTask(function()
  while true do
    mp.wait(1000)
    print('uptime', mp.getTimer())
  end
end)
```

## Повтор и отмена

`setInterval` нет, таймаут отменить нельзя. Используйте задачу с флагом:

```lua
local running = true

mp.spawnTask(function()
  while running do
    -- periodic work
    mp.wait(5000)
  end
end)

-- later
running = false
```

## Остановка ресурса

При остановке ресурса его состояние Lua закрывается: задачи, таймауты и колбэки `mp.onUpdateLoop` заканчиваются вместе с ним. Код после `mp.wait`, который ещё не продолжился, не выполнится никогда, поэтому не используйте `mp.wait` в обработчиках `resourceStop`.
