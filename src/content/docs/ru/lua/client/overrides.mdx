---
title: Override (Lua)
description: Замена игровых методов и вызов продолжения цепочки.
---

`mp.override(className, methodName, callback)` заменяет вызов игрового метода. Обработчик решает, вызвать ли продолжение цепочки и что вернуть игре.

## Подготовка

Только клиент. Укажите `use_game_natives = true` в `resource.toml`. Зарегистрируйте хуки один раз после инициализации игровых классов; [стадии инициализации](/ru/lua/client/game-natives).

```toml title="resource.toml"
client_script = 'client.lua'
use_game_natives = true
```

## Регистрация

```lua title="client.lua"
mp.registerGameState('onInit', function()
  mp.override('PlayerPuppet', 'OnDeath', function(self, evt, wrappedMethod)
    print('Player death callback')
    return wrappedMethod(evt)
  end)
end)
```

## Аргументы

Передайте точное имя класса и REDscript-имя метода из [NativeDB](https://nativedb.red4ext.com/). Для перегруженного метода используйте полную сигнатуру с суффиксом после `;`. Имя переменной `self` произвольное.

- Метод экземпляра: `callback(self, arg1, ..., wrappedMethod)`.
- Статический метод: `callback(arg1, ..., wrappedMethod)` — без `self`.
- `wrappedMethod(arg1, ...)` вызывает следующее звено цепочки. Не передавайте в него `self`: контекст экземпляра уже сохранён.
- Функция продолжения действует только внутри текущего вызова. Не сохраняйте её для таймера или другого обработчика.

## Порядок выполнения

Обработчик выполняется синхронно. Вызов `wrappedMethod(...)` продолжает цепочку; если других замен нет, вызывается исходный метод. Несколько замен выполняются в порядке регистрации, и каждая сама решает, продолжать ли цепочку. Если не вызвать `wrappedMethod`, оставшаяся цепочка и исходный метод не выполнятся.

Возвращайте значение нужного игрового типа. `return false` здесь означает результат метода, а не специальную команду отмены события. Для сохранения поведения используйте `return wrappedMethod(...)`. Не вызывайте тот же метод через `self`: это может снова войти в ваш override.

Не используйте `mp.wait` и не откладывайте вызов продолжения. 

## Примеры

Статический метод: пример из `cybermp_core` блокирует вызов транспорта и возвращает `true`, не вызывая продолжение. Первый аргумент — `GameInstance`, а не `self`.

```lua title="client.lua"
mp.registerGameState('onInit', function()
  mp.override('VehicleSystem', 'IsSummoningVehiclesRestricted;GameInstance',
    function(game, wrappedMethod)
      return true
    end)
end)
```

`cybermp_core/client/lua/main.lua` также заменяет `PlayerPuppet.OnDeath`, `VehicleObject.OnMountingEvent` и другие методы по флагам `[core.overrides]`. Учитывайте уже включённые замены: продолжение может вызвать следующий хук, а не сразу ванильный метод. Примеры выше показывают альтернативные схемы; не регистрируйте одну замену повторно.

Для методов с выходными параметрами возвращайте основной результат, затем выходные значения в порядке объявления. В Lua это несколько возвращаемых значений; `return wrappedMethod(...)` передаёт их все.

## Очистка

Регистрация не возвращает публичный id для снятия хука. При остановке или перезапуске ресурса его хуки снимаются автоматически. Для временного отключения проверяйте флаг внутри обработчика; в отключённом override вызывайте продолжение. Регистрируйте хуки один раз на экземпляр ресурса, а не на каждом вызове команды или повторной загрузке мира.

## Проверка проблем

Проверьте `use_game_natives`, стадию регистрации, имя класса, полную сигнатуру и факт вызова метода игрой. Начните с наблюдателя и короткого сообщения в журнале. Если замена не сохраняет поведение, проверьте аргументы `wrappedMethod`, отсутствие `self` в вызове продолжения и возвращаемый тип.
