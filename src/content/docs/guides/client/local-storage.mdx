`mp.localStorage` is a small key-value store saved on the player's own machine. What you put there is still there after the player restarts the game or reconnects, so it suits per-player preferences that the server has no reason to keep: HUD layout, volume, keybinds, "don't show this again" flags.

It is not a place for anything that matters to gameplay. The data lives on the player's PC, the server never sees it unless you send it, and the player can change or delete it.

Full signatures are in the [`MpLocalStorage`](/reference/client/api/global/mplocalstorage/) reference and the [Lua client reference](/reference/lua/client/#local-storage-mplocalstorage).

## The five functions

| Function | What it does |
| :--- | :--- |
| `set(key, value)` | Stores a string under `key`, replacing any previous value. The value must be a non-empty string. |
| `get(key)` | Returns the stored value as **JSON-encoded text** (see below). |
| `delete(key)` | Removes one key. |
| `deleteAll()` | Removes every key in the store. |
| `save()` | Writes the store to disk. |

Three things trip people up. Each is covered below:

1. Nothing is written to disk until you call `save()`.
2. `get()` doesn't return exactly what you passed to `set()`: it returns it wrapped as JSON text.
3. The store is shared by all resources of the server.

:::caution[Always call `save()`]
`set()`, `delete()` and `deleteAll()` only change the copy in memory. Nothing is saved automatically. If the game closes before you call `mp.localStorage.save()`, those changes are gone. Call `save()` right after you write or remove something.
:::

## Storing and reading values

Values are strings. To store a number, an object or a table, turn it into a string first, usually with JSON.

Reading needs one extra step. `get()` returns the stored string JSON-encoded: after `set('hud_theme', 'neon')`, `get('hud_theme')` returns `"neon"` *with the quotes*, and a key that doesn't exist comes back as the text `null`. So decode what `get()` returns once to get your string back. If that string is itself JSON you wrote, decode it a second time.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Returns the stored string, or null when the key is missing
    const readString = (key) => {
      const raw = mp.localStorage.get(key);
      if (!raw) return null;
      try {
        return JSON.parse(raw); // unwrap the JSON encoding added by the store
      } catch {
        return raw;
      }
    };

    // Write a plain string and an object
    mp.localStorage.set('hud_theme', 'neon');
    mp.localStorage.set('user_keybinds', JSON.stringify({ openPhone: 'T', toggleRadio: 'R' }));
    mp.localStorage.save(); // write to disk

    // Read them back
    const theme = readString('hud_theme'); // 'neon'

    const keybindsJson = readString('user_keybinds'); // '{"openPhone":"T",...}'
    const keybinds = keybindsJson ? JSON.parse(keybindsJson) : {};

    console.log(`Theme: ${theme}, phone key: ${keybinds.openPhone}`);
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Returns the stored string, or nil when the key is missing
    local function readString(key)
      local raw = mp.localStorage.get(key)
      if not raw or raw == '' or raw == 'null' then return nil end
      return json.decode(raw) -- unwrap the JSON encoding added by the store
    end

    -- Write a plain string and a table
    mp.localStorage.set('hud_theme', 'neon')
    mp.localStorage.set('user_keybinds', json.encode({ openPhone = 'T', toggleRadio = 'R' }))
    mp.localStorage.save() -- write to disk

    -- Read them back
    local theme = readString('hud_theme') -- 'neon'

    local keybindsJson = readString('user_keybinds') -- '{"openPhone":"T",...}'
    local keybinds = keybindsJson and json.decode(keybindsJson) or {}

    print(string.format("Theme: %s, phone key: %s", theme, keybinds.openPhone))
    ```
  </TabItem>
</Tabs>

## Example: a settings object with defaults

Real settings are rarely one value. Store them as one object under one key, and never trust what comes back: on a player's first visit there is nothing saved, an older version of your resource may have saved fewer settings, and the player can edit the file by hand. `loadSettings` below always returns a complete, usable object. It starts from the defaults and only takes a saved value when it is a setting you know and has the type you expect.

The example uses the `readString` helper from the previous section and connects the settings to a [CEF page](/guides/client/first-cef-ui/): the page receives them when it loads and reports each change.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Prefixed with the resource name: the store is shared with other resources
    const SETTINGS_KEY = 'myresource:settings';

    // What a player gets before they change anything
    const DEFAULT_SETTINGS = {
      hudScale: 1.0,
      showSpeedometer: true,
      chatFontSize: 14,
    };

    const loadSettings = () => {
      // Start from a copy of the defaults
      const settings = Object.assign({}, DEFAULT_SETTINGS);

      // Nothing saved yet: this is the player's first visit
      const savedJson = readString(SETTINGS_KEY);
      if (!savedJson) return settings;

      let savedSettings = null;
      try {
        savedSettings = JSON.parse(savedJson);
      } catch {
        // The saved text is damaged: keep the defaults
        return settings;
      }
      if (savedSettings === null || typeof savedSettings !== 'object') return settings;

      // Take over only the settings we know, and only with the expected type
      for (const settingName of Object.keys(DEFAULT_SETTINGS)) {
        const savedValue = savedSettings[settingName];
        if (typeof savedValue === typeof DEFAULT_SETTINGS[settingName]) {
          settings[settingName] = savedValue;
        }
      }

      return settings;
    };

    const saveSettings = (settings) => {
      mp.localStorage.set(SETTINGS_KEY, JSON.stringify(settings));
      mp.localStorage.save();
    };

    const settings = loadSettings();

    // The page has loaded: give it the settings to display
    mp.events.onCef('domReady', () => {
      mp.events.emitCef('settingsLoaded', settings);
    });

    // The player changed one setting in the page
    mp.events.onCef('settingChanged', (settingName, newValue) => {
      // The page is not trusted blindly either: skip unknown names and wrong types
      const defaultValue = DEFAULT_SETTINGS[settingName];
      if (defaultValue === undefined) return;
      if (typeof newValue !== typeof defaultValue) return;

      settings[settingName] = newValue;
      saveSettings(settings);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Prefixed with the resource name: the store is shared with other resources
    local SETTINGS_KEY = 'myresource:settings'

    -- What a player gets before they change anything
    local DEFAULT_SETTINGS = {
      hudScale = 1.0,
      showSpeedometer = true,
      chatFontSize = 14,
    }

    local function loadSettings()
      -- Start from a copy of the defaults
      local settings = {}
      for settingName, defaultValue in pairs(DEFAULT_SETTINGS) do
        settings[settingName] = defaultValue
      end

      -- Nothing saved yet: this is the player's first visit
      local savedJson = readString(SETTINGS_KEY)
      if not savedJson then return settings end

      -- pcall catches the error json.decode raises on damaged text
      local decodedOk, savedSettings = pcall(json.decode, savedJson)
      if not decodedOk or type(savedSettings) ~= 'table' then return settings end

      -- Take over only the settings we know, and only with the expected type
      for settingName, defaultValue in pairs(DEFAULT_SETTINGS) do
        local savedValue = savedSettings[settingName]
        if type(savedValue) == type(defaultValue) then
          settings[settingName] = savedValue
        end
      end

      return settings
    end

    local function saveSettings(settings)
      mp.localStorage.set(SETTINGS_KEY, json.encode(settings))
      mp.localStorage.save()
    end

    local settings = loadSettings()

    -- The page has loaded: give it the settings to display
    mp.events.addCef('domReady', function()
      mp.events.triggerCef('settingsLoaded', settings)
    end)

    -- The player changed one setting in the page
    mp.events.addCef('settingChanged', function(settingName, newValue)
      -- The page is not trusted blindly either: skip unknown names and wrong types
      local defaultValue = DEFAULT_SETTINGS[settingName]
      if defaultValue == nil then return end
      if type(newValue) ~= type(defaultValue) then return end

      settings[settingName] = newValue
      saveSettings(settings)
    end)
    ```
  </TabItem>
</Tabs>

Why it is built this way:

- **New settings just work.** Add a key to `DEFAULT_SETTINGS` in a later version and players who saved the old object get the default for it. A key you remove is dropped the next time the object is saved.
- **`save()` writes the whole store to disk.** That is fine for a checkbox. For a slider that reports dozens of changes while it is dragged, update the object on every change but call `saveSettings` once, when the player lets go or closes the settings screen.
- **One key, not one key per setting.** A single object is read and written in one go and leaves a single entry to prefix, version or delete.
- **Settings stay on this PC.** A player on another computer starts from the defaults again. Preferences that should follow the account belong on the server.

## Deleting entries

`delete(key)` removes one entry and `deleteAll()` empties the store. Both need a `save()` afterwards, like any other change.

    // Remove a single key
    mp.localStorage.delete('hud_theme');
    mp.localStorage.save();

    // Remove everything in the store
    mp.localStorage.deleteAll();
    mp.localStorage.save();

## Who shares the store

- **One store per server.** Storage is separated by server address (`ip:port`), so what your server saves is not visible to another server the player joins.
- **Shared by all resources of that server.** Every resource reads and writes the same store. Prefix your keys with the resource name (for example `'myresource:settings'`) so two resources don't overwrite each other, and remember that `deleteAll()` wipes the other resources' keys too.
- **Client only.** Nothing here reaches the server by itself. If the server needs a stored preference, send it with a [server event](/guides/client/events/).
