In CyberMP the client script puts the player into the world: you choose a position and call `spawnPlayer`. A working spawn has three parts, covered in order on this page: give the player health, call the spawn method, and do both only once the game world has loaded.

The spawn method is [`mp.local.spawnPlayer`](/reference/client/api/global/mplocal/#spawnplayer) in JavaScript and [`mp.client.spawnPlayer`](/reference/lua/client/#local-entities-mpclient) in Lua.

:::note
The health code below calls game native functions, which only work when your `resource.toml` enables them:
```toml title="resource.toml"
use_game_natives = true
```
See [Working with Game Natives](/reference/client/working-with-game-natives) for how native calls work.
:::

## Set the player's health

Set the health before you spawn. Otherwise the character can enter the world with an empty health pool and flatline on the spot.

The game stores health in two places:

- A **stat** holds the maximum. You change it by adding a *modifier* to the stat.
- A **stat pool** holds the current value, which goes up and down between zero and that maximum.

Both are identified by game enum values:

| Constant | Value | Game enum |
| :--- | :--- | :--- |
| Health stat pool | `17` | `gamedataStatPoolType.Health` ([NativeDB](https://nativedb.red4ext.com/e/5923428624360168)) |
| Health stat | `787` | `gamedataStatType.Health` ([NativeDB](https://nativedb.red4ext.com/e/8958699713058621)) |
| Additive modifier | `0` | `gameStatModifierType.Additive` ([NativeDB](https://nativedb.red4ext.com/e/5896876661927857)) |

`setMaxHealth` replaces the modifiers on the health stat, and `setHealth` sets the current value of the pool:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    const HEALTH_STAT_POOL_TYPE = 17;
    const HEALTH_STAT_TYPE = 787;
    const ADDITIVE_MODIFIER_TYPE = 0;

    const setHealth = (value) => {
      const player = mp.game.GetPlayer();
      const playerGameId = player.GetEntityID();
      const statPoolsSystem = mp.game.ScriptGameInstance.GetStatPoolsSystem();

      statPoolsSystem.RequestSettingStatPoolValueIgnoreChangeMode(
        playerGameId,
        HEALTH_STAT_POOL_TYPE,
        value,
        new mp.game.gameObject(),
        false
      );
    };

    const setMaxHealth = (value) => {
      const player = mp.game.GetPlayer();
      const playerGameId = player.GetEntityID();

      // Drop the existing health modifiers, then add ours
      const statsSystem = mp.game.ScriptGameInstance.GetStatsSystem();
      statsSystem.RemoveAllModifiers(playerGameId, HEALTH_STAT_TYPE, true);

      const modifier = new mp.game.gameConstantStatModifierData_Deprecated();
      modifier.statType = HEALTH_STAT_TYPE;
      modifier.modifierType = ADDITIVE_MODIFIER_TYPE;
      modifier.value = value;
      statsSystem.AddModifier(playerGameId, modifier);

      const statPoolsSystem = mp.game.ScriptGameInstance.GetStatPoolsSystem();
      statPoolsSystem.RequestSettingStatPoolValueIgnoreChangeMode(
        playerGameId,
        HEALTH_STAT_POOL_TYPE,
        value,
        new mp.game.gameObject(),
        true
      );
    };
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    local HEALTH_STAT_POOL_TYPE = 17
    local HEALTH_STAT_TYPE = 787
    local ADDITIVE_MODIFIER_TYPE = 0

    local function setHealth(value)
      local player = Game.GetPlayer()
      local playerGameId = player:GetEntityID()
      local statPoolsSystem = Game.GetStatPoolsSystem()

      statPoolsSystem:RequestSettingStatPoolValueIgnoreChangeMode(
        playerGameId,
        HEALTH_STAT_POOL_TYPE,
        value,
        nil,
        false
      )
    end

    local function setMaxHealth(value)
      local player = Game.GetPlayer()
      local playerGameId = player:GetEntityID()

      -- Drop the existing health modifiers, then add ours
      local statsSystem = Game.GetStatsSystem()
      statsSystem:RemoveAllModifiers(playerGameId, HEALTH_STAT_TYPE, true)

      local modifier = NewObject('gameConstantStatModifierData_Deprecated')
      modifier.statType = HEALTH_STAT_TYPE
      modifier.modifierType = ADDITIVE_MODIFIER_TYPE
      modifier.value = value
      statsSystem:AddModifier(playerGameId, modifier)

      local statPoolsSystem = Game.GetStatPoolsSystem()
      statPoolsSystem:RequestSettingStatPoolValueIgnoreChangeMode(
        playerGameId,
        HEALTH_STAT_POOL_TYPE,
        value,
        nil,
        true
      )
    end
    ```
  </TabItem>
</Tabs>

## Spawn the player

`spawnPlayer(x, y, z, yaw)` takes a world position and the direction the character faces. Set the maximum health first, then the current health, then spawn.

A spawn point is easier to read and to pass around as one value with named fields, so the helper below takes it in that form:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    const SPAWN_HEALTH = 300;

    // Next to V's apartment in Megabuilding H10
    const DEFAULT_SPAWN = { x: -1392.637, y: 1271.536, z: 123.082, yaw: 1.0 };

    const spawnPlayerAt = (spawnPoint) => {
      setMaxHealth(SPAWN_HEALTH);
      setHealth(SPAWN_HEALTH);

      mp.local.spawnPlayer(spawnPoint.x, spawnPoint.y, spawnPoint.z, spawnPoint.yaw);
    };
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    local SPAWN_HEALTH = 300

    -- Next to V's apartment in Megabuilding H10
    local DEFAULT_SPAWN = { x = -1392.637, y = 1271.536, z = 123.082, yaw = 1.0 }

    local function spawnPlayerAt(spawnPoint)
      setMaxHealth(SPAWN_HEALTH)
      setHealth(SPAWN_HEALTH)

      mp.client.spawnPlayer(spawnPoint.x, spawnPoint.y, spawnPoint.z, spawnPoint.yaw)
    end
    ```
  </TabItem>
</Tabs>

:::caution[The spawn is asynchronous]
`spawnPlayer` returns `true` when the spawn sequence has *started*, not when the character is ready. For a short while afterwards `GetPlayer()` can return nothing, and `GetGender()` on a fresh puppet can still report `None`. If you customize the character right after spawning (appearance, clothing, inventory), wait for the puppet first: see [Waiting for the puppet after a spawn](/guides/client/lifecycle/#waiting-for-the-puppet-after-a-spawn).
:::

## Call it when the world is ready

Game natives and world systems don't exist yet when your script starts, so a spawn at the top of the script or in `resourceStart` fails. Wait for the game-loaded stage. The "once" variant used here runs on the first world load only, which is what you want for the initial spawn. [Client Lifecycle & Stages](/guides/client/lifecycle) explains all the stages.

A console command is handy for respawning by hand while you develop. Client commands are typed in the client console, which opens with `F8`:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Spawn automatically when the world is ready
    mp.game.onceGameLoaded(() => {
      spawnPlayerAt(DEFAULT_SPAWN);
    });

    // Type "spawn" in the client console (F8) to respawn
    mp.commands.add('spawn', () => {
      spawnPlayerAt(DEFAULT_SPAWN);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Spawn automatically when the world is ready
    mp.registerGameState('onceGameLoaded', function()
      spawnPlayerAt(DEFAULT_SPAWN)
    end)

    -- Type "spawn" in the client console (F8) to respawn
    mp.commands.add('spawn', function()
      spawnPlayerAt(DEFAULT_SPAWN)
    end)
    ```
  </TabItem>
</Tabs>

:::tip[Close menus before respawning]
If the pause or settings menu is open when you spawn, it can stay stuck and freeze the player's input. Close the menus first, with the `closeAllMenus` helper from [Teleporting the Player](/guides/client/teleporting-player).
:::

## Respawning at the nearest spawn point

`spawnPlayer` also works on a character who is dead: it puts them back into the world at the position you give, and the health code above brings them back to full health. So a respawn is the same call as the first spawn, and the only question is where.

A common answer is "the closest point from a list". The example keeps a list of respawn points, measures the distance from the character to each of them, and spawns at the closest one. It runs when the server sends a `respawn` event, because the server is the one that knows a player died (its [`playerDeath`](/guides/server/players/#death-respawn-and-disconnect) event) and decides when they may come back.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    const RESPAWN_POINTS = [
      { name: 'Megabuilding H10', x: -1392.637, y: 1271.536, z: 123.082, yaw: 1.0 },
      { name: 'Afterlife', x: -1456.89, y: 1038.27, z: 16.82, yaw: 1.0 },
    ];

    // Straight-line distance between two points in the world
    const getDistance = (from, to) => {
      const deltaX = from.x - to.x;
      const deltaY = from.y - to.y;
      const deltaZ = from.z - to.z;
      return Math.sqrt(deltaX * deltaX + deltaY * deltaY + deltaZ * deltaZ);
    };

    const findNearestRespawnPoint = (position) => {
      let nearestPoint = RESPAWN_POINTS[0];
      let nearestDistance = getDistance(position, nearestPoint);

      for (const respawnPoint of RESPAWN_POINTS) {
        const distance = getDistance(position, respawnPoint);
        if (distance < nearestDistance) {
          nearestPoint = respawnPoint;
          nearestDistance = distance;
        }
      }

      return nearestPoint;
    };

    mp.events.onServer('respawn', () => {
      const player = mp.game.GetPlayer();

      // Without a character there is no position to measure from
      if (!player) {
        spawnPlayerAt(DEFAULT_SPAWN);
        return;
      }

      // A dead character still has a position: it is where they died
      const deathPosition = player.GetWorldPosition();
      const respawnPoint = findNearestRespawnPoint(deathPosition);

      spawnPlayerAt(respawnPoint);
      console.log(`Respawned at ${respawnPoint.name}`);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    local RESPAWN_POINTS = {
      { name = 'Megabuilding H10', x = -1392.637, y = 1271.536, z = 123.082, yaw = 1.0 },
      { name = 'Afterlife', x = -1456.89, y = 1038.27, z = 16.82, yaw = 1.0 },
    }

    -- Straight-line distance between two points in the world
    local function getDistance(from, to)
      local deltaX = from.x - to.x
      local deltaY = from.y - to.y
      local deltaZ = from.z - to.z
      return math.sqrt(deltaX * deltaX + deltaY * deltaY + deltaZ * deltaZ)
    end

    local function findNearestRespawnPoint(position)
      local nearestPoint = RESPAWN_POINTS[1]
      local nearestDistance = getDistance(position, nearestPoint)

      for _, respawnPoint in ipairs(RESPAWN_POINTS) do
        local distance = getDistance(position, respawnPoint)
        if distance < nearestDistance then
          nearestPoint = respawnPoint
          nearestDistance = distance
        end
      end

      return nearestPoint
    end

    mp.events.addServer('respawn', function()
      local player = Game.GetPlayer()

      -- Without a character there is no position to measure from
      if not player then
        spawnPlayerAt(DEFAULT_SPAWN)
        return
      end

      -- A dead character still has a position: it is where they died
      local deathPosition = player:GetWorldPosition()
      local respawnPoint = findNearestRespawnPoint(deathPosition)

      spawnPlayerAt(respawnPoint)
      print('Respawned at ' .. respawnPoint.name)
    end)
    ```
  </TabItem>
</Tabs>

Things to know before you build on this:

- **Collect your own coordinates.** Stand where you want a respawn point and print your position; [Working with Game Natives](/reference/client/working-with-game-natives/#reading-the-players-position) has a command for that.
- **The server is not asked where.** The position is chosen on the client, so a modified client can respawn anywhere. If the place matters (a prison, a faction base), let the server pick the point and send its coordinates with the event.
- **Distance is measured in a straight line**, through walls and floors. With points on different levels of a megabuilding, the closest one is not always the quickest to reach.
- **Send the event after a delay** if you want a death screen first. Nothing respawns the player between the death and your event.
