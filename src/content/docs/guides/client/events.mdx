On the client, `mp.events` addresses three targets: the local script, the server, and the HTML UI.

<Tabs syncKey="client-events-side">
<TabItem label="Local">

[`on`](/reference/client/api/events/mpevents#on) / [`emit`](/reference/client/api/events/mpevents#emit) stay on this client.

```js title="client.js"
mp.events.on('resourceStart', () => {
  console.log('The client resource has successfully started.');
});

mp.events.on('vehicleStreamIn', (netID, gameID) => {
  console.log(`Vehicle streamed in - NetID: ${netID}, GameID: ${gameID}`);
});

mp.events.on('myCustomLocalEvent', (data) => {
  console.log('Received local data:', data);
});

mp.events.emit('myCustomLocalEvent', 'Hello local script!');
```

</TabItem>
<TabItem label="Server">

[`emitServer`](/reference/client/api/events/mpevents#emitserver) / [`onServer`](/reference/client/api/events/mpevents#onserver). Return value: [RPC](/guides/general/rpc).

```js title="client.js"
mp.events.emitServer(
  'requestVehicleSpawn',
  'Vehicle.v_standard2_archer_hella',
);

mp.events.onServer('serverNotification', (message) => {
  console.log(`[Server]: ${message}`);
});
```

</TabItem>
<TabItem label="CEF">

[`onCef`](/reference/client/api/events/mpevents#oncef) / [`emitCef`](/reference/client/api/events/mpevents#emitcef). UI page: [CEF UI](/guides/client/first-cef-ui).

Besides what the page sends with `mp.events.emit`, the CEF process (`CEFSubProcess.exe`) emits two built-in events into every frame: `domReady` on `DOMContentLoaded` (argument: the frame's `window.name`) and `loadingFailed` on any uncaught JS error or unhandled promise rejection in the page ([`CefLoadingFailedError`](/reference/client/api/events/cefloadingfailederror)). `loadingFailed` is not a network/HTTP load error.

```js title="client.js"
mp.events.onCef('domReady', (frameName) => {
  mp.events.emitCef('initializeDashboard', { playerName: 'V', initialHealth: 300 });
});

mp.events.onCef('loadingFailed', (error) => {
  console.error(`CEF Load Failed in ${error.frameName}: ${error.message}`);
});

mp.events.onCef('uiButtonPressed', (buttonId) => {
  console.log(`Player clicked UI button: ${buttonId}`);
});
```

</TabItem>
</Tabs>

## Cleanup

Named handlers, then [`off`](/reference/client/api/events/mpevents#off). `off` removes handlers registered with `on` only. `onServer` and `onCef` store the handler under an internal prefixed name (and `onCef` wraps it), so `off(name, fn)` does not find them; `offCef` does not remove `onCef` handlers either. Guard such handlers with a flag; they are dropped when the resource stops.

```js title="client.js"
const handlePlayerStream = (netID, gameID) => {
  console.log(`Player ${netID} streamed in.`);
};

mp.events.on('remotePlayerStreamIn', handlePlayerStream);
mp.events.off('remotePlayerStreamIn', handlePlayerStream);
```

Stream events: `vehicleStreamIn` / `Out`, `remotePlayerStreamIn` / `Out`, `pedStreamIn` / `Out`, `objectStreamIn` / `Out` — `(netID, gameID)`. Convert ids with [`mp.network`](/guides/client/network-and-local).

Resource events: `resourceStart`, `resourceStop` (this resource), `anyResourceStart`, `anyResourceStop`, `anyClientResourceStart`, `anyClientResourceStop` (resource name as the argument). `resourcesRefresh` and `anyServerResourceStart` / `anyServerResourceStop` are server-only.
