Every connected player is an entity on the server. You get its ID from events such as `playerConnected`, turn that ID into a player object with `mp.players.at(id)`, and then read its state (nickname, position, health, vehicle), send it events, or kick it.

One thing to know up front: the server mostly *reads* players. The only properties you can assign are `dimension` and `streamingRadius`. To heal, teleport or respawn someone, you send an event to that player's client and let a client script do it, see [Spawning the player](/guides/client/spawning-player/) and [Teleporting the player](/guides/client/teleporting-player/).

## Player lifecycle

These are the events a player goes through, from joining to leaving:

| Event | Arguments | When it fires |
| :--- | :--- | :--- |
| `playerConnecting` | `tempId`, `name` | A client starts connecting. The player has no permanent ID yet. |
| `playerConnected` | `playerId`, `tempId` | The connection is complete and the player has its network ID. |
| `playerSpawn` | `playerId` | The player's character appears in the world. |
| `playerDeath` | `playerId`, `data` | The player dies. `data.killerId` is set when another player did it. |
| `playerRespawn` | `playerId`, `data` | The player comes back after dying. `data.posX`, `data.posY`, `data.posZ` hold the position. |
| `playerDespawn` | `playerId` | The player despawns. |
| `playerDisconnected` | `playerId`, `reason` | The player left the server. |

All of them give you a numeric player ID, not a player object.

### Connection and spawning

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // A client is connecting. Only a temporary ID and the name are known.
    mp.events.on('playerConnecting', (tempId, name) => {
      console.log(`${name} is connecting (temp ID ${tempId})`);
    });

    // The player now has its permanent network ID.
    mp.events.on('playerConnected', (playerId, tempId) => {
      const player = mp.players.at(playerId);
      console.log(`${player.nickname} joined with ID ${playerId}`);
    });

    // The character is in the world.
    mp.events.on('playerSpawn', (playerId) => {
      const player = mp.players.at(playerId);
      const [x, y, z] = player.position;
      console.log(`${player.nickname} spawned at [${x}, ${y}, ${z}]`);

      // Put the player in the shared world, and let them see entities up to 250 meters away.
      player.dimension = 0;
      player.streamingRadius = 250;
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- A client is connecting. Only a temporary ID and the name are known.
    mp.events.add('playerConnecting', function(tempId, name)
      print(string.format("%s is connecting (temp ID %s)", name, tempId))
    end)

    -- The player now has its permanent network ID.
    mp.events.add('playerConnected', function(playerId, tempId)
      local player = mp.players.at(playerId)
      print(string.format("%s joined with ID %s", player.nickname, playerId))
    end)

    -- The character is in the world.
    mp.events.add('playerSpawn', function(playerId)
      local player = mp.players.at(playerId)
      local position = player.position
      print(string.format("%s spawned at [%s, %s, %s]", player.nickname, position[1], position[2], position[3]))

      -- Put the player in the shared world, and let them see entities up to 250 meters away.
      -- In Lua the radius must be a decimal number: `250` without `.0` is ignored.
      player.dimension = 0
      player.streamingRadius = 250.0
    end)
    ```
  </TabItem>
</Tabs>

### Death, respawn and disconnect

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // The killer may have left in the meantime, so check before reading the name.
    function getKillerName(killerId) {
      if (mp.players.exists(killerId)) {
        return mp.players.at(killerId).nickname;
      }
      return `player ${killerId}`;
    }

    mp.events.on('playerDeath', (playerId, data) => {
      const victim = mp.players.at(playerId);

      if (data.killerId) {
        console.log(`${victim.nickname} was flatlined by ${getKillerName(data.killerId)}`);
      } else {
        console.log(`${victim.nickname} died`);
      }
    });

    mp.events.on('playerRespawn', (playerId, data) => {
      const player = mp.players.at(playerId);
      console.log(`${player.nickname} respawned at [${data.posX}, ${data.posY}, ${data.posZ}]`);
    });

    mp.events.on('playerDisconnected', (playerId, reason) => {
      console.log(`Player ${playerId} disconnected: ${reason}`);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- The killer may have left in the meantime, so check before reading the name.
    local function getKillerName(killerId)
      if mp.players.exists(killerId) then
        return mp.players.at(killerId).nickname
      end
      return string.format("player %s", killerId)
    end

    mp.events.add('playerDeath', function(playerId, data)
      local victim = mp.players.at(playerId)

      if data.killerId then
        print(string.format("%s was flatlined by %s", victim.nickname, getKillerName(data.killerId)))
      else
        print(string.format("%s died", victim.nickname))
      end
    end)

    mp.events.add('playerRespawn', function(playerId, data)
      local player = mp.players.at(playerId)
      print(string.format("%s respawned at [%s, %s, %s]", player.nickname, data.posX, data.posY, data.posZ))
    end)

    mp.events.add('playerDisconnected', function(playerId, reason)
      print(string.format("Player %s disconnected: %s", playerId, reason))
    end)
    ```
  </TabItem>
</Tabs>

:::caution
In `playerDisconnected` the player may already be gone, so don't count on `mp.players.at(playerId)` there. Use the ID to clean up your own data (anything you keyed by player ID). If you need the nickname at that point, store it yourself when the player connects.
:::

### Example: join and leave announcements

This tells everyone when a player joins or leaves. It remembers each nickname at connection time, because the player object is no longer usable when `playerDisconnected` fires.

`chat:add` is a custom event, not a built-in one: you need a client script that listens for it and shows the text (see [client events](/guides/client/events/#communicating-with-the-server)).

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Nickname of every connected player, by player ID.
    const nicknames = new Map();

    function sendToEveryone(message) {
      for (const player of mp.players.toArray()) {
        player.emit('chat:add', message);
      }
    }

    // If this resource is restarted while people are online, playerConnected
    // does not fire again for them, so pick their nicknames up here.
    for (const player of mp.players.toArray()) {
      nicknames.set(player.id, player.nickname);
    }

    mp.events.on('playerConnected', (playerId) => {
      const player = mp.players.at(playerId);
      nicknames.set(playerId, player.nickname);

      sendToEveryone(`${player.nickname} joined the server.`);
    });

    mp.events.on('playerDisconnected', (playerId, reason) => {
      const nickname = nicknames.get(playerId) || `Player ${playerId}`;
      nicknames.delete(playerId);

      sendToEveryone(`${nickname} left the server (${reason}).`);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Nickname of every connected player, by player ID.
    local nicknames = {}

    local function sendToEveryone(message)
      for _, player in ipairs(mp.players.toArray()) do
        player:trigger('chat:add', message)
      end
    end

    -- If this resource is restarted while people are online, playerConnected
    -- does not fire again for them, so pick their nicknames up here.
    for _, player in ipairs(mp.players.toArray()) do
      nicknames[player.id] = player.nickname
    end

    mp.events.add('playerConnected', function(playerId)
      local player = mp.players.at(playerId)
      nicknames[playerId] = player.nickname

      sendToEveryone(string.format("%s joined the server.", player.nickname))
    end)

    mp.events.add('playerDisconnected', function(playerId, reason)
      local nickname = nicknames[playerId] or string.format("Player %s", playerId)
      nicknames[playerId] = nil

      sendToEveryone(string.format("%s left the server (%s).", nickname, reason))
    end)
    ```
  </TabItem>
</Tabs>

Deleting the entry on disconnect matters: a table keyed by player ID that is never cleaned grows for as long as the server runs.

## Finding players

`mp.players` is the pool of connected players:

- `mp.players.exists(id)` tells you whether that player is still connected.
- `mp.players.at(id)` returns the player object.
- `mp.players.toArray()` returns every connected player.

A typical use is turning something a person typed (an ID, or part of a name) into a player object:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Accepts a player ID ("12") or part of a nickname ("jack").
    // Returns the player object, or null when nobody matches.
    function findPlayer(query) {
      const playerId = Number(query);
      if (!Number.isNaN(playerId) && mp.players.exists(playerId)) {
        return mp.players.at(playerId);
      }

      const searchedName = String(query).toLowerCase();
      for (const player of mp.players.toArray()) {
        if (player.nickname.toLowerCase().includes(searchedName)) {
          return player;
        }
      }

      return null;
    }
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- In Lua, mp.players.exists(id) also says yes for the ID of a vehicle, ped or object.
    -- Reading the entity type as well makes sure the ID belongs to a connected player.
    local PLAYER_ENTITY_TYPE = 1

    local function isConnectedPlayer(id)
      return mp.players.exists(id) and mp.players.at(id).type == PLAYER_ENTITY_TYPE
    end

    -- Accepts a player ID ("12") or part of a nickname ("jack").
    -- Returns the player object, or nil when nobody matches.
    function findPlayer(query)
      local playerId = tonumber(query)
      if playerId and isConnectedPlayer(playerId) then
        return mp.players.at(playerId)
      end

      local searchedName = string.lower(tostring(query))
      for _, player in ipairs(mp.players.toArray()) do
        -- The last two arguments make string.find search for plain text, not a Lua pattern.
        if string.find(string.lower(player.nickname), searchedName, 1, true) then
          return player
        end
      end

      return nil
    end
    ```
  </TabItem>
</Tabs>

### Example: a "who is online" command

`toArray()` is also how you count and list players. This registers an `online` [command](/guides/server/commands/) that works from the server console and from a player's F8 console.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    function describeOnlinePlayers() {
      const players = mp.players.toArray();
      if (players.length === 0) {
        return 'Nobody is online.';
      }

      const names = players.map((player) => `${player.nickname} (${player.id})`);
      return `${players.length} online: ${names.join(', ')}`;
    }

    mp.commands.add('online', (player) => {
      const text = describeOnlinePlayers();

      // From the server console there is no player to answer, so print instead.
      const fromConsole = !player || player.id === 0;
      if (fromConsole) {
        console.log(text);
      } else {
        player.emit('chat:add', text);
      }
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    local function describeOnlinePlayers()
      local players = mp.players.toArray()
      if #players == 0 then
        return 'Nobody is online.'
      end

      local names = {}
      for _, player in ipairs(players) do
        table.insert(names, string.format("%s (%s)", player.nickname, player.id))
      end
      return string.format("%s online: %s", #players, table.concat(names, ', '))
    end

    mp.commands.add('online', function(player)
      local text = describeOnlinePlayers()

      -- From the server console there is no player to answer, so print instead.
      local fromConsole = player == 0
      if fromConsole then
        print(text)
      else
        player:trigger('chat:add', text)
      end
    end)
    ```
  </TabItem>
</Tabs>

`toArray()` builds a new list of player objects on every call. That is fine for a command; in code that runs many times per second, call it once and reuse the result.

:::caution[Check `exists()` before `at()`]
An ID you kept from earlier can belong to a player who has since left. In JS, `mp.players.at(id)` then returns `undefined` and the next property access throws. In Lua, `mp.players.at(id)` itself raises an error. Calling `mp.players.exists(id)` first avoids both.
:::

:::caution[Lua: `mp.players.exists` does not check that the ID is a player]
In server-side Lua the pools do not look at the kind of entity: `mp.players.exists(id)` returns `1` for the ID of any existing entity, a vehicle or a ped included, and `mp.players.at(id)` then hands you that entity. For an ID your own code got from a player event this makes no difference. For an ID that a person typed or a client sent, also compare the entity's `type` with `1` (player), as `isConnectedPlayer` does above. In JavaScript, `mp.players.exists` only accepts players.

Note the return values too: Lua's `exists` gives `1` or `false`, not `true`. Use it directly in an `if`; `mp.players.exists(id) == true` never matches.
:::

:::note[Compare players by ID]
A player object is a thin wrapper around the ID, and a new wrapper is created on every call. `mp.players.at(5) === mp.players.at(5)` is `false`. Compare `playerA.id === playerB.id` instead (`playerA.id == playerB.id` in Lua).
:::

## Player properties

A player object stores nothing but the ID. Every property is read live from the server at the moment you access it, so `player.position` is always current, and if you need the same value several times in a row, read it once into a local variable.

| Property | Type | Writable | Description |
| :--- | :--- | :--- | :--- |
| `id` | `number` | No | Network ID assigned by the server. |
| `nickname` | `string` | No | Display name. |
| `health` | `number` | No | Current health points. |
| `position` | `[x, y, z]` | No | World coordinates. |
| `rotation` | `[pitch, roll, yaw]` | No | Orientation. |
| `yaw` | `number` | No | Heading in degrees. |
| `velocity` | `[x, y, z]` | No | Movement velocity. |
| `ping` | `number` | No | Network latency in milliseconds. |
| `ip` | `string` | No | Remote IP address. |
| `vehicle` | vehicle | No | The vehicle the player is in. On foot: `null` in JS; in Lua, a vehicle object whose `id` is `0`. |
| `lastVehicle` | vehicle | No | The vehicle the player was in before. Same empty value as `vehicle`. |
| `exist` | `boolean` | No | Whether the player is still connected. |
| `dimension` | `number` | Yes | The virtual world the player is in (`0` is the shared world). See [Virtual dimensions](#virtual-dimensions). |
| `streamingRadius` | `number` | Yes | The distance at which this player streams in and out. |

*Streaming* means sending an entity to a client. A client doesn't receive everything on the server, only what is close enough to it; the streaming radius is that distance.

Everything else is read-only. The full list of members is on the [`MpPlayer`](/reference/server/api/entities/players/mpplayer/) reference page; for Lua, see [Player Objects](/reference/lua/server/#player-objects).

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    function logPlayerSnapshot(player) {
      // position is an array: [x, y, z]
      const [x, y, z] = player.position;
      console.log(`${player.nickname} (ID ${player.id})`);
      console.log(`Position: [${x.toFixed(2)}, ${y.toFixed(2)}, ${z.toFixed(2)}], yaw ${player.yaw.toFixed(1)}`);
      console.log(`Health: ${player.health} | Ping: ${player.ping} ms | IP: ${player.ip}`);

      if (player.vehicle) {
        console.log(`In vehicle #${player.vehicle.id}`);
      }
    }
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    function logPlayerSnapshot(player)
      -- position is indexed from 1: x, y, z
      local position = player.position
      print(string.format("%s (ID %s)", player.nickname, player.id))
      print(string.format("Position: [%.2f, %.2f, %.2f], yaw %.1f", position[1], position[2], position[3], player.yaw))
      print(string.format("Health: %s | Ping: %s ms | IP: %s", player.health, player.ping, player.ip))

      -- An empty vehicle reads as an object whose id is 0
      if player.vehicle and player.vehicle.id ~= 0 then
        print(string.format("In vehicle #%s", player.vehicle.id))
      end
    end
    ```
  </TabItem>
</Tabs>

## Interacting with players

### Sending an event to one player

Call `emit` on the player object (`trigger` in Lua), or use `mp.events.emitClient` (`mp.events.triggerClient` in Lua) when you only have the ID.

The event names below are made up for the example. Nothing happens on the client until one of your client scripts listens for them, see [client events](/guides/client/events/#communicating-with-the-server).

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // When you have the player object
    function showContractReward(player, amount) {
      player.emit('ui:showNotification', {
        title: 'Contract Completed',
        amount: amount
      });
    }

    // When you only have the ID, for example inside a platform event
    mp.events.on('playerSpawn', (playerId) => {
      mp.events.emitClient(playerId, 'ui:showNotification', {
        title: 'Welcome to Night City',
        amount: 0
      });
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- When you have the player object
    function showContractReward(player, amount)
      player:trigger('ui:showNotification', {
        title = 'Contract Completed',
        amount = amount
      })
    end

    -- When you only have the ID, for example inside a platform event
    mp.events.add('playerSpawn', function(playerId)
      mp.events.triggerClient(playerId, 'ui:showNotification', {
        title = 'Welcome to Night City',
        amount = 0
      })
    end)
    ```
  </TabItem>
</Tabs>

To reach everyone, loop over `mp.players.toArray()` as `sendToEveryone` does [above](#example-join-and-leave-announcements); in Lua you can also pass `-1` instead of a player to `mp.events.triggerClient`.

### Kicking and muting

`kick` disconnects a player; the reason is optional. In JS, kicking an ID that is no longer connected does nothing, so you don't need to guard the call.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    function kickCheater(player) {
      player.kick('Exploiting game mechanics');
    }

    // Same thing when you only have the ID
    function kickCheaterById(playerId) {
      mp.players.kick(playerId, 'Exploiting game mechanics');
    }
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    function kickCheater(player)
      player:kick('Exploiting game mechanics')
    end

    -- Same thing when you only have the ID
    ```

:::caution[Muting does nothing yet]
Players also have a `mute` method (`player.mute()` in JS, `player:mute(enable)` in Lua), meant to silence their voice chat. On server v4.0.4-beta.1 it has no effect: the call only logs a warning and the player can still be heard. [Voice chat](/guides/server/voice-chat/#the-script-api) has the details and what you can do in the meantime.
:::

## Tracking combat and weapons

The server is told when players deal damage, shoot, swing a melee weapon or throw a grenade.

:::caution[`damage`: the first argument is the attacker]
In the `damage` event the first argument is the ID of the player who **dealt** the damage. The player who was hit is `data.victimId`.
:::

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    mp.events.on('damage', (attackerId, data) => {
      if (!mp.players.exists(data.victimId)) return;

      const victim = mp.players.at(data.victimId);
      console.log(`${victim.nickname} took ${data.totalDamage} damage from player ${attackerId}`);
      console.log(`Weapon hash: ${data.weaponHash} | Damage type: ${data.damageType}`);
    });

    mp.events.on('shootAction', (playerId, data) => {
      console.log(`Player ${playerId} fired weapon ${data.weaponHash} at [${data.posX}, ${data.posY}, ${data.posZ}]`);
    });

    mp.events.on('meleeAction', (playerId, data) => {
      console.log(`Player ${playerId} did melee action type ${data.type}`);
    });

    mp.events.on('throwGrenade', (playerId, data) => {
      console.log(`Player ${playerId} threw a grenade (quick throw: ${data.isQuickThrow})`);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    mp.events.add('damage', function(attackerId, data)
      if not mp.players.exists(data.victimId) then return end

      local victim = mp.players.at(data.victimId)
      print(string.format("%s took %s damage from player %s", victim.nickname, data.totalDamage, attackerId))
      print(string.format("Weapon hash: %s | Damage type: %s", data.weaponHash, data.damageType))
    end)

    mp.events.add('shootAction', function(playerId, data)
      print(string.format("Player %s fired weapon %s at [%s, %s, %s]", playerId, data[1], data[3], data[4], data[5]))
    end)

    mp.events.add('meleeAction', function(playerId, data)
      print(string.format("Player %s did melee action type %s", playerId, data[1]))
    end)

    mp.events.add('throwGrenade', function(playerId, data)
      print(string.format("Player %s threw a grenade (quick throw: %s)", playerId, tostring(data[3])))
    end)
    ```
  </TabItem>
</Tabs>

The fields of each payload are listed in the [`PlayersEvents`](/reference/server/api/events/players/playersevents/) reference (JS) and the [Lua event catalog](/reference/lua/server/#platform-event-catalog). To block damage, return `false` from the handler, see [Cancelling platform events](/guides/server/events/#cancelling-platform-events). To recognise a weapon from `data.weaponHash`, see [Working with Hashes](/guides/server/hashes/#comparing-hashes).

## Virtual dimensions

A dimension is a numbered copy of the world. Players and entities only see and touch what is in the same dimension as them, so two players standing on the same spot in different dimensions never meet.

- Dimension `0` is the default, shared world.
- Any other number is a separate instance. Use them for apartment interiors or instanced missions.

Move a player by assigning `player.dimension`. Vehicles, peds, objects and pickups have the same property.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Give each apartment its own dimension
    function enterApartment(player, apartmentId) {
      player.dimension = 1000 + apartmentId;
    }

    // Back to the shared world
    function exitApartment(player) {
      player.dimension = 0;
    }
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Give each apartment its own dimension
    function enterApartment(player, apartmentId)
      player.dimension = 1000 + apartmentId
    end

    -- Back to the shared world
    function exitApartment(player)
      player.dimension = 0
    end
    ```
  </TabItem>
</Tabs>

The numbers are yours to choose, as long as they are whole numbers; nothing has to be created before you use a dimension. In Lua a decimal number is not accepted even when it is whole (`4.0` is misread, `4` works), so if `apartmentId` could arrive as a decimal, for example from a client, assign `1000 + math.floor(apartmentId)`. Just keep the ranges of your different systems apart (here apartments start at `1000`) so that two features never pick the same number by accident.

Changing the dimension does not move the player. To also put them inside the interior, send an event to their client and teleport there, see [Teleporting into another dimension](/guides/client/teleporting-player/#teleporting-into-another-dimension).
