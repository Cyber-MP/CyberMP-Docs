Server scripts receive platform and network traffic through `mp.events`. Connections, deaths, vehicle interaction, and client packets arrive here.

## Platform and custom events

[`mp.events.on`](/reference/server/api/events/mpevents#on) registers handlers for platform lifecycle events (connect, death, vehicles) and for custom events emitted inside the server process.

```js title="server.js"
mp.events.on('playerConnected', (playerId, tempId) => {
    console.log(`Player connected - assigned Network ID: ${playerId}`);
});

mp.events.on('playerDeath', (playerId, data) => {
    if (data.killerId) {
      console.log(`Player ${playerId} was flatlined by Killer ID: ${data.killerId}`);
    } else {
      console.log(`Player ${playerId} flatlined due to environmental damage.`);
    }
});

mp.events.on('logServerActivity', (action, details) => {
    console.log(`[Activity Log] Action: ${action} | ${details}`);
});

mp.events.emit('logServerActivity', 'Database', 'Initial connection established.');
```

## Client packets

A client script sends a packet with [`emitServer`](/reference/client/api/events/mpevents#emitserver). The server receives it on [`mp.events.onClient`](/reference/server/api/events/mpevents#onclient). For a return value, use [RPC](/guides/general/rpc) instead of a pair of events.

The handler receives the sending **`player`** (`MpPlayer`) as the first argument. Do not take the player id from payload data: the client can spoof it.

```js title="server.js"
mp.events.onClient('requestVehicleSpawn', (player, modelHash, x, y, z) => {
  console.log(`Player ${player.nickname} (${player.id}) requested to spawn: ${modelHash}`);
});
```

## Events to clients

[`mp.events.emitClient`](/reference/server/api/events/mpevents#emitclient) sends an event to one client. The first argument is the target: an [`MpPlayer`](/reference/server/api/entities/players/mpplayer/) instance or a numeric `playerId`. `-1` sends the event to all players; `0`, `null` and `undefined` are rejected with an error log.

```js title="server.js"
mp.events.on('playerSpawn', (playerId) => {
  mp.events.emitClient(playerId, 'serverNotification', 'Welcome back to Night City.');
});

mp.events.on('vehicleHittedByPlayer', (playerId, data) => {
  // data is an array: [vehicleID, componentNameHash, weaponHash, byOwner]
  const [vehicleId, , , byOwner] = data;
  if (byOwner) {
    mp.events.emitClient(playerId, 'uiNotification', `You damaged your own vehicle ${vehicleId}!`);
  }
});
```

## Removing handlers

[`mp.events.off`](/reference/server/api/events/mpevents#off) unregisters a named function previously passed to [`mp.events.on`](/reference/server/api/events/mpevents#on). It does not remove [`mp.events.onClient`](/reference/server/api/events/mpevents#onclient) handlers: they are stored under an internal prefixed event name, and `off(name, fn)` looks under the plain name. Use this when a module unloads.

```js title="server.js"
const trackExplosions = (playerId, data) => {
  console.log(`Explosion tracked at coordinate cluster: [${data.posX}, ${data.posY}]`);
};

mp.events.on('explosion', trackExplosions);
mp.events.off('explosion', trackExplosions);
```

## Cancelling the default action

Some platform events are typed `void | boolean`. Return `false` from the handler so the engine skips its own action (vanilla heal, knockdown, door, explosion). Any other return value, or none, lets the action run.

```js title="server.js"
mp.events.on('playerHealing', (playerId) => {
  return false;
});

mp.events.on('doorStateChange', (playerId, data) => {
  if (restrictedDoors.has(data.hashObject)) {
    return false;
  }
});
```

- Only a value returned synchronously counts. An `async` handler returns a Promise and cannot cancel.
- With several handlers, one `false` is enough. All handlers still run.
- `mp.cancelEvent()` was removed. Replace it with `return false`.

Cancelling without matching client state leaves the player inconsistent (a door appears open while the state is still closed). Verify on a single case first.

`mp.isServer()` returns `true` on the server process.
