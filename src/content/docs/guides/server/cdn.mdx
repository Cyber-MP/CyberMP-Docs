title: CDN
description: Learn how to offload resource file delivery to an external CDN, reducing server bandwidth and speeding up client downloads.
---

By default, clients download every file listed in a resource's [`file`](/guides/resources/adding-resource-files) array directly from the dedicated server. This includes CEF UI assets, `.archive` / `.xl` packs, and tweak files. For servers with many players or large custom assets, this can saturate the server's upload bandwidth and slow down connection times.

A **resource CDN** lets you host those files on an external HTTP server (or a traditional CDN provider) so that clients fetch them from a fast, dedicated download endpoint instead of the game server itself.

:::note
Resource CDN is available on [Server Manager plans](/guides/server-manager/subscriptions) starting from **Bronze**. If the listing plan is below Bronze, the server logs a warning and falls back to serving files through its built-in file server.
:::

---

## How It Works

When CDN is enabled, the dedicated server process separates into two concerns:

**The server process retains:**
- `server.toml` configuration and all `server_script` logic
- Entity streaming, events, and RPC
- The `file` allow-list (clients still validate downloads against it)

**The CDN hosts:**
- The packed client files of every started resource that is **not** marked as `server_only` — this includes `resource.toml`, `client_script` and all `file` entries

Typical CDN-hosted assets include:

| Asset type | Examples |
| :--- | :--- |
| Game archives | Vehicle packs, clothing, weapons (`.archive`) |
| REDmod / ArchiveXL extras | `.xl` files, tweak overrides |
| UI assets | Images, bundled HTML/CSS/JS for CEF |

:::tip
If you use [hot reload](/guides/recipes/hotreload) during development, keep frequently edited HTML and JS files inside the resource rather than on the CDN. Hot reload watches local resource files — changes pushed to the CDN won't be detected automatically.
:::

## Setting Up CDN

### Step 1 — Pack the client files

Run the server with the `--justpack` flag. This loads `server.toml`, starts all resources, writes the packed client files along with a `connect.json` manifest into a `cdn_upload/` directory, and then exits:

```shell
# Windows
cybermp-server.exe -run --justpack

# Linux
./cybermp-server -run --justpack
```

You can optionally pass `--host=<ip>` and `--port=<port>` if your server binds to a non-default address.

### Step 2 — Upload to your CDN

Upload the **entire contents** of the `cdn_upload/` directory to the root of your CDN domain. The directory structure must be preserved exactly as generated — clients will request files by their relative paths.

### Step 3 — Configure `server.toml`

Add the following keys to your `server.toml` and start the server normally:

```toml title="server.toml"
useCdn = true
cdnUrl = "https://cdn.example.com"
```

:::caution
These keys are not exposed on the [`ServerConfig`](/reference/server/api/global/config/serverconfig/) type directly — in `mp.config` they fall under its index signature. Do not attempt to read them as typed properties.
:::

## Re-packing After Changes

Every time you add, remove, or update resource files (new archives, updated UI builds, etc.), you need to repeat the pack-and-upload cycle:

1. Stop the server (or run a separate instance with `--justpack`)
2. Re-run with `--justpack` to regenerate `cdn_upload/`
3. Upload the updated files to your CDN
4. Restart the server

## Core Files

The built-in `cybermp_core` resource includes core files located in `cybermp_core/files/` that are configured via the `core.files` setting. These files must be streamed to clients for proper connection. When packaging files for CDN via `--justpack`, ensure these files are packed and uploaded to your CDN. See the [`[core]` section](/reference/server/configuration) of the server configuration reference for the complete list of required files.
