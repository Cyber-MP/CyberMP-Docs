When you change a script, you don't need to restart the whole server. Restarting just the resource you edited is enough: the server stops it and loads its files again from disk.

## Prerequisites
- A running CyberMP Server.
- Access to the [server console](/reference/server/console).
- A running resource, for example `hello_world` from the [previous](/guides/resources/creating-resource) guide.

## Steps

<Steps>
    1. #### Modify the script

        <Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
            <TabItem label="JS">
                Open `resources/hello_world/server.js` and add a new line of code:

                ```js title="server.js" ins={2}
                console.log('Hello World from CyberMP Server!');
                console.log('The resource has been updated live!');
                ```
            </TabItem>
            <TabItem label="Lua">
                Open `resources/hello_world/server.lua` and add a new line of code:

                ```lua title="server.lua" ins={2}
                print('Hello World from CyberMP Server!')
                print('The resource has been updated live!')
                ```
            </TabItem>
        </Tabs>

        Saving the file changes nothing yet: the server keeps running the version it loaded earlier.

    2. #### Restart the resource
        In the server console, type `restart` followed by the resource folder name:
        ```shell
        restart hello_world
        ```

    3. #### Check the output
        The server stops the old instance, then runs the new code. Your console shows:
        ```ansi
        [38;2;179;133;0m[00:00:00] [resources][0m Stopped resource hello_world
        [38;2;179;133;0m[00:00:00] [hello_world][0m Hello World from CyberMP Server!
        [38;2;179;133;0m[00:00:00] [hello_world][0m The resource has been updated live!
        [38;2;179;133;0m[00:00:00] [resources][0m Loaded resource hello_world
        >
        ```

</Steps>

## What a restart resets

A restart throws the old script instance away and runs the file again from the top, so its variables, event handlers, commands and timers (`setTimeout`, `setInterval`) start from scratch. The resource gets a `resourceStop` event before it stops and a `resourceStart` event when it starts again. (`resourceStop` belongs to `stop` and `restart` only: it does not fire when the server itself shuts down with `quit`, so [don't save data there](/guides/server/saving-data/#when-to-save).)

:::caution
Entities created by the resource (vehicles, peds, objects, pickups) are **not** removed when it stops. Destroy them in a `resourceStop` handler, otherwise every restart leaves another copy in the world.
:::

Two things are **not** reset, because they live in the server and not in your script:

| Survives a restart | What to do about it |
| :--- | :--- |
| Entities the resource created | Destroy them in `resourceStop` (see the caution above). |
| Global [metadata](/guides/server/meta/) | Nothing, usually. It is a handy place for small state you want to keep across restarts while developing. |

Connected players stay connected too, and `playerConnected` does not fire again for them. If your script builds per-player state in that event, also build it at startup for the players who are already there:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
    <TabItem label="JS">
        ```js title="server.js"
        function setUpPlayer(player) {
          console.log(`Setting up ${player.nickname}`);
        }

        mp.events.on('playerConnected', (playerId) => {
          setUpPlayer(mp.players.at(playerId));
        });

        // After a restart: players who connected before this script was loaded.
        for (const player of mp.players.toArray()) {
          setUpPlayer(player);
        }
        ```
    </TabItem>
    <TabItem label="Lua">
        ```lua title="server.lua"
        local function setUpPlayer(player)
          print(string.format("Setting up %s", player.nickname))
        end

        mp.events.add('playerConnected', function(playerId)
          setUpPlayer(mp.players.at(playerId))
        end)

        -- After a restart: players who connected before this script was loaded.
        for _, player in ipairs(mp.players.toArray()) do
          setUpPlayer(player)
        end
        ```
    </TabItem>
</Tabs>

## Client-side updates

The restart command also applies to client scripts. When you restart a resource on the server, all connected clients automatically re-download and restart that resource's client-side scripts.

## Automated updates

If typing `restart` after every save gets tedious, you can automate it. The [Hotreload](/guides/recipes/hotreload) recipe shows how to watch your files and restart the resource when they change.
