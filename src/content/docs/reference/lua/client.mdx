The client-side Lua API runs inside the game process. Names, signatures and return values below follow the runtime implementation in `libs/client/lua`. Hashes and the game layer are available only in a resource that sets `use_game_natives = true`.

## Client Events (`mp.events`)

The client event dispatcher routes communication across three targets: the local script, the server, and the CEF page.

### Registration and Removal

<a id="mp-events-add-clientref"></a>

#### mp.events.add(name, fn)

> **mp.events.add**(`name`, `fn`): `handlerId`

Registers a platform or custom local handler. Returns a numeric handler id.

<a id="mp-events-addserver"></a>

#### mp.events.addServer(name, fn)

> **mp.events.addServer**(`name`, `fn`): `handlerId`

Server → Client. Receives what the server sends with `mp.events.triggerClient`. Returns a numeric handler id.

<a id="mp-events-addcef"></a>

#### mp.events.addCef(name, fn)

> **mp.events.addCef**(`name`, `fn`): `token`

CEF → Client. Receives what the page sends with `mp.events.emit`. Returns a table token.

<a id="mp-events-trigger-clientref"></a>

#### mp.events.trigger(name, ...)

> **mp.events.trigger**(`name`, `...`)

Local. Fires a local event. Handlers run in their own coroutine, so `mp.wait` works inside them.

<a id="mp-events-triggerserver-clientref"></a>

#### mp.events.triggerServer(name, ...)

> **mp.events.triggerServer**(`name`, `...`)

Client → Server. Sends a reliable packet. The server receives it in `mp.events.addClient`.

<a id="mp-events-triggercef"></a>

#### mp.events.triggerCef(name, ...)

> **mp.events.triggerCef**(`name`, `...`)

Client → CEF. Sends an event to the page, which receives it in `mp.events.on`.

<a id="mp-events-remove-clientref"></a>

#### mp.events.remove(name, id)

> **mp.events.remove**(`name`, `id`): `nil`

Local. Removes a handler by the numeric id returned by `add` or `addServer`.

<a id="mp-events-removecef"></a>

#### mp.events.removeCef(name, token)

> **mp.events.removeCef**(`name`, `token`): `nil`

CEF → Client. Removes a CEF handler. `token` is the table returned by `addCef`.

`mp.events.remove` is looked up by `name` too: it searches the `add` handlers of that name first and only then the `addServer` handlers of the same name. Pass the id, not the function; a function is not a valid key. `mp.events.removeCef` needs the exact token table, not the id. Handlers are dropped automatically when the resource stops. There is no event cancel on the client in Lua: the return value of a client handler is ignored.

Use [Network Mapping](#network-mapping-mpnetwork) to convert `netID` to `gameID` and back.

### CEF Page Events

The CEF process emits two built-in events into every frame. Register both with `mp.events.addCef`.

<a id="domready"></a>

#### domReady(frameName)

> **domReady**(`frameName`): `nil`

The frame fired `DOMContentLoaded`; `frameName` is its `window.name` string.

<a id="loadingfailed"></a>

#### loadingFailed(err)

> **loadingFailed**(`err`): `nil`

An uncaught page error or unhandled promise rejection. `err` is a table with `frameName`, `message`, `source`, `line`, `column` and `stack`. It is not a network or HTTP load error.

The page sends with `mp.events.emit(name, ...)`. Arguments are serialized as JSON: no arguments arrive as nothing, a single argument arrives as one value, several arguments arrive as separate Lua arguments, and one object arrives as one table.

## Local Storage (`mp.localStorage`)

A string key-value store on the local machine. It is not replicated to the server. There is one store per server address, shared by all resources of that server, so prefix your keys and remember that `deleteAll()` clears the store for every resource.

<a id="mplocalstorage-set"></a>

### mp.localStorage.set(key, value)

> **mp.localStorage.set**(`key`, `value`): `nil`

Stores a non-empty string. An empty value is rejected and logged.

<a id="mplocalstorage-get"></a>

### mp.localStorage.get(key)

> **mp.localStorage.get**(`key`): `string`

Returns the value **JSON-encoded**: `'"abc"'` for `'abc'`, and `'null'` for a missing key. Never returns `nil`.

<a id="mplocalstorage-delete"></a>

### mp.localStorage.delete(key)

> **mp.localStorage.delete**(`key`): `nil`

Removes one key from memory.

<a id="mplocalstorage-deleteall"></a>

### mp.localStorage.deleteAll()

> **mp.localStorage.deleteAll**(): `nil`

Clears the whole store from memory.

<a id="mplocalstorage-save"></a>

### mp.localStorage.save()

> **mp.localStorage.save**(): `nil`

Writes the store to disk. Nothing is saved automatically.

Serialize tables yourself and unwrap the JSON encoding on read. Because the stored value is a JSON string, a value written with `json.encode` is encoded twice and needs two `json.decode` calls.

## Discord Integration (`mp.discord`)

The client talks to the Discord desktop app. Everything here is client-only.

<a id="mp-discord-updaterichpresence"></a>

### mp.discord.updateRichPresence(state, details)

> **mp.discord.updateRichPresence**(`state`, `details`): `nil`

Sets the two presence lines. `''` empties a line; the CyberMP card and timer stay.

<a id="mp-discord-getcodeauthorization"></a>

### mp.discord.getCodeAuthorization(appId, scopes)

> **mp.discord.getCodeAuthorization**(`appId`, `scopes`): `string`

Returns a one-time **authorization code**, or `''` while pending. `scopes` is a JSON array string such as `'["identify","guilds"]'`.

<a id="mp-discord-getoauth2token"></a>

### mp.discord.getOAuth2Token(appId)

> **mp.discord.getOAuth2Token**(`appId`): `string`

Returns an **access token** from the Discord Game SDK, or `''` while pending. The SDK is initialized once with the first app id passed.

The official client JS typings declare a second parameter, `getOAuth2Token(discordAppId, scopes)`; whether the Lua function reads it was not verified.

Both authorization calls are asynchronous: the first call starts the request and returns an empty string, the value arrives on a later call, and the code is returned once. If Discord is not running they keep returning an empty string, so always validate the result. Exchange the authorization code on **your server**; never put a Discord client secret in a client resource.

## Per-Frame Tick Loop

<a id="mp-onupdateloop-clientref"></a>

### mp.onUpdateLoop(fn)

> **mp.onUpdateLoop**(`fn`): `nil`

Registers `fn` for every script tick. There is no way to remove the callback, and an error inside it is dropped without a message, so guard the body with a flag and keep it cheap.

<a id="mp-setimmediate-clientref"></a>

### mp.setImmediate(fn, ...)

> **mp.setImmediate**(`fn`, `...`): `nil`

The client-only deferred queue. Calls `fn(...)` on a later tick, up to 256 callbacks per tick. An error inside the callback is printed as `Error in immediate callback: ...`. The observe wrappers use this queue internally.

For periodic work use a task instead: a task can wait, a tick callback cannot.

## Game Layer (`use_game_natives = true`)

### Global Classes & Constructors


#### Game

> **Game**

Game instance and global functions: `Game.GetPlayer()`, `Game.GetStatsSystem()`, `Game.GetStatPoolsSystem()`, `Game.GetTeleportationFacility()`. Call object methods with `:`.

The built-in core resource (`cybermp_core/dist/main.lua`) also uses `Game.FindEntityByID(id)`, `Game.GetStatusEffectSystem()` and the global `GetPlayer()`.

<a id="newobject"></a>

#### NewObject(typeName)

> **NewObject**(`typeName`): `object` | `nil`

Instantiates a REDengine class by name, for example `NewObject('ForceCloseHubMenuEvent')`. Returns `nil` when the type is unknown.

Game classes are also exposed as globals with a `.new()` constructor, and enums as globals indexed by member name. The core resource uses both forms: `gameDeathEvent.new()`, `TweakDBID.new('GameplayRestriction.NoCombat')`, `vehicleCameraPerspective.TPPMedium`.

Engine singleton, native proxy, type check and enum conversion.

<a id="game-value-types"></a>

#### CName, TweakDBID, ItemID, CRUID, LocKey

> **CName**, **TweakDBID**, **ItemID**, **CRUID**, **LocKey**

Game value types and their `To*` helpers. `CName('name')` and `TweakDBID('name')` build a hash from a string; `ToCName(table)`, `ToTweakDBID(table)` and `ToItemID(table)` build one from a table of fields.

Names, signatures and enums of game classes are listed on [NativeDB](https://nativedb.red4ext.com/); the names there match the names you call from Lua.

### Game Lifecycle Stages

<a id="mp-registergamestate"></a>

#### mp.registerGameState(stage, fn)

> **mp.registerGameState**(`stage`, `fn`): `nil`

Registers a callback for a game lifecycle stage. Handlers run on the next script tick after the stage; if the stage was already reached when the resource started, they run on the first tick.

| Stage | When | Arguments |
| :--- | :--- | :--- |
| `onTweak` | TweakDB is ready. | — |
| `onInit` | Game runtime initialized; `Game` calls become usable. | — |
| `onGameLoaded` | The world is loaded. Runs on every load. | — |
| `onceGameLoaded` | The first world load after registration only. | — |
| `onUpdate` | Every tick after `onInit`. | `dt` |
| `onInputKeyEvent` | A key event. | `action, key` |

<a id="mp-isontweakcalled"></a>

#### mp.isOnTweakCalled()

> **mp.isOnTweakCalled**(): `boolean`

`true` once the `onTweak` stage has passed.

<a id="mp-isoninitcalled"></a>

#### mp.isOnInitCalled()

> **mp.isOnInitCalled**(): `boolean`

`true` once the `onInit` stage has passed.

<a id="mp-isongameloadedcalled"></a>

#### mp.isOnGameLoadedCalled()

> **mp.isOnGameLoadedCalled**(): `boolean`

`true` once the `onGameLoaded` stage has passed.

Register events and commands at resource start and keep every `Game.*` call behind the appropriate stage. `Game.GetPlayer()` can still return `nil` right after `mp.client.spawnPlayer`; poll for the puppet before health, appearance or teleport work.

<a id="mp-override"></a>

#### mp.override(typeName, methodName, fn)

> **mp.override**(`typeName`, `methodName`, `fn`): `nil`

Replaces the method. Synchronous. `fn` receives `self, arg1, ..., wrappedMethod` (or `arg1, ..., wrappedMethod` for a static method) and returns the value the game method expects, then the out parameters in declaration order.

"Before" describes the capture point, not the time the user callback runs: a queued observer body can execute after the game method has already finished. Observer return values are ignored.

Callback arguments:

- Instance method: `fn(self, arg1, ...)`.
- Static method: `fn(arg1, ...)`, without `self`.
- Override: `fn(self, arg1, ..., wrappedMethod)`, or `fn(arg1, ..., wrappedMethod)` for a static method.
- An overloaded method is selected by its full signature with the suffix after `;`, for example `'IsSummoningVehiclesRestricted;GameInstance'`.
- `self` is a weak reference. A stored controller can be invalid after it closes or unloads.

`wrappedMethod(...)` calls the next link in the chain and finally the original method. Do not pass `self` to it: the instance context is retained by the runtime. The continuation is valid only during the override call. Omitting `wrappedMethod` skips the rest of the chain and the original method. Overrides run synchronously; do not defer the continuation with `mp.wait`. Keep Raw callbacks short: they run inside the game call.
