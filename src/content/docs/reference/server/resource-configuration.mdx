Every resource has a `resource.toml` file in its folder. It is the manifest: it tells the server which scripts to run on which side, which page to load as the UI and which extra files players have to download. The folder name is the resource's name; the manifest doesn't set it.

For an introduction to resources themselves, see [Introduction to resources](/guides/resources/introduction).

## TOML schema & example

To get autocomplete and validation in editors that support TOML schemas (such as the Even Better TOML VS Code extension), add the schema header at the top of the file:

```toml title="resource.toml"
#:schema https://schemas.cyber.mp/resource/schema.json

server_script = './server/index.js'
client_script = './client/index.js'

cef_url = './ui/index.html'
file = ['./ui/*', './assets/*']

use_game_natives = true
```

All paths are relative to the resource folder.

## Keys

Every key is optional. A resource with only `server_script` never sends anything to players; one with only `client_script` runs in the game only.

A list of scripts is loaded in the order you write it:

```toml title="resource.toml"
client_script = ['./dist/client.js', './dist/main.lua']
```

## Other keys

The six keys above are the ones defined by the [official schema](https://schemas.cyber.mp/resource/schema.json). The manifest accepts keys beyond them, and the server ignores those it doesn't know. Two uses are common:

- **Describing the resource.** Keys such as `author`, `description` and `version` are plain metadata for whoever reads the file.
- **Passing options to other resources.** A resource can read any manifest with `mp.resources.getTOML(name)` in JavaScript (`mp.resources.getTomlFile(name)` in Lua). The [hotreload](/guides/recipes/hotreload) watcher works this way: it restarts the resources whose manifest contains `hotreload = true`.

After you change a `resource.toml` while the server is running, type [`refresh`](/reference/server/console) in the server console so the server reads it again, then `restart` the resource.
